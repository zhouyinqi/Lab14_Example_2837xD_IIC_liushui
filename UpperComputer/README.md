# HPD控制模组测试上位机

## Board Protocol Smoke Test

After downloading the Debug firmware and connecting Ethernet, run this command
from the project root:

```powershell
python .\UpperComputer\Tools\protocol_smoke_test.py
```

The script sends only `PING` and `GET_STATUS`; it does not start a test or drive
any output. Both replies must show `protocolStatus: 0`.
该目录是独立的 Qt 6 Windows 桌面工程，与 `../HPD_BoardTest_DSP` 同级，不再嵌套于 DSP 工程。`../platforms` 是保留的 Android 示例，不参与这两个工程的构建。

## 当前功能

- TCP 连接 DSP1 的 W5300 或 W5500，默认地址为 `192.168.1.111:12001`。
- DSP 自动识别 W5300/W5500 硬件配置；板型由操作员独立选择并确认，两者不互相绑定。
- 三个一键按钮：板载自检、外设连接后自检、HPD注入模拟量自检。
- 单项测试、DO安全确认、状态轮询和结果记录表。
- Test ID下拉框随结果区宽度伸缩；展开列表按最长名称加宽，超出屏幕时可横向滚动，悬停可查看完整名称。
- DO/PWM-DIDO结果确认框采用非阻塞处理，等待人工确认时仍正常轮询DSP；仅选择“是”才标记PASS，选择“否”或关闭确认框标记FAIL。重新测试或切换板型会作废旧确认框，不覆盖新结果。
- 以太网测试重配 W5300/W5500 期间，客户端每2秒自动重连；连续自动重连10次失败后停止，需手动点击“连接”重新开始。
- 协议使用固定长度帧和 CRC16，旧 `BTST -> BTOK` 连通性测试保持兼容。

## 构建

在 Qt Creator 中打开本目录的 `CMakeLists.txt`，选择 Qt 6 Windows Desktop Kit 构建运行。工程需要 `Qt6::Widgets`、`Qt6::Network` 和 `Qt6::SerialPort`。

迁移后须从新位置打开工程，不能沿用旧位置的 CMake 缓存。已重新生成的 Debug 程序位于 `build/Desktop_Qt_6_11_1_MinGW_64_bit_Debug/HpdBoardTestHost.exe`。CAN 驱动仍放在程序旁的 `CanDriver/ZLG32`，保留其中完整的 `kerneldlls` 子目录。

## DSP协议

请求为12字节：`BT`、版本、命令、序号、阶段、标志、参数、CRC16。

响应为40字节：`BR`、版本、命令、序号、协议状态、测试管理器状态、单条记录、CRC16。所有16/32位字段均为大端序；浮点数为IEEE-754单精度大端序。

当前命令包括：连接检测、三类自动测试、停止、单项测试、读取状态、读取单条记录、读取板型信息、读取Test ID状态和配置ADC外部注入参数。DO/HDO/PWM-DIDO/驱动复位单项测试必须携带输出解锁标志，Qt界面会要求人工确认。

## 低空经济统型板 DIDO

低空经济统型板V01使用DSP直连DIDO，不经过FPGA。协议继续复用`0x0315 DI_EXTERNAL`和`0x0313 DO_EXTERNAL`：

- DI：`EX_DI1/2/3`内部对应`GPIO42/89/90`。PLC的三路DO分别接入三路板卡DI，并按约1秒周期翻转；DSP在30秒窗口内要求每一路都出现高、低和跳变。
- DO：`EX_DOP1/2/3`内部对应`GPIO43/67/88`。DSP按1、2、3顺序输出，每路置位约2秒后清零；操作员观察对应PLC DI指示灯并在Qt中确认。
- 测试结束、失败或收到“停止”命令后，三路DSP DO都恢复为低电平。首次实板验证前状态保持`待验证`。

PLC公共端、板卡`CME/DIx_CME`和24V供电按实际PLC源型/漏型输出及板卡端子原理图连接，不把DSP的`DGND/AGND`作为24V DIDO回路公共端。

### PWM-DIDO

低空经济统型板V01把PWM端子作为普通DIDO验证，不产生真实PWM波形。`0x031F PWM_DIDO_EXTERNAL`由Qt选择`PWM1H、PWM1L`至`PWM6H、PWM6L`中的一路；所选通道输出约2秒的5V后回到0V，由操作员对当前一路确认。

点击开始前先接好表笔，观察开始后的两秒输出窗口。人工确认框是在输出结束、恢复0V后出现，不能仅凭确认框出现后的0V判定失败。

12路输出必须保持独立，禁止互相并联，也禁止向PWM输出端反向注入信号发生器的5V。万用表使用直流电压档，黑表笔接`DGND`，红表笔接Qt当前所选PWM端子；也可使用示波器或5V逻辑分析仪。S7-1200为24V DI，只有增加5V转24V隔离模块后才能连接。管脚表中四路`D_1UPWM_EN/D_1DPWM_EN/D_2UPWM_EN/D_2DPWM_EN`为高电平有效；固件在测试当前绕组时同步打开对应的U/D使能。四路`POW_EN`始终保持GPIO低电平。测试结束、失败或停止后，12路PWM、四路`D_*PWM_EN`和四路`POW_EN`全部恢复低电平。该项仅单项运行，实板验证前状态为`待验证`。

U11/U12的`D_ENPWM1/D_ENPWM2`是`SN74LVC4245A`的低有效`/OE`，与上述四路高有效`D_*PWM_EN`不能直接视为同一信号。`/OE=1`时U11/U12隔离，后级输入被200k电阻下拉，PWM端子会保持0V；`/OE=0`且`DIR=0`时才会把3.3V侧`D_PWMx`送到5V侧`PWMx`。现有管脚表没有给出`D_ENPWM1/2`的DSP GPIO，须根据完整原理图核对它们与四路`D_*PWM_EN`之间的逻辑后，才能修改固件使能策略。

`0x031F`采用非阻塞状态机保持所选GPIO约2秒，期间网络协议仍可应答。Qt每200ms读取一次运行记录并显示DSP GPIO数字读回以及约`3.3V/0V`的逻辑折算值；这不是ADC模拟电压实测值。运行记录的`rawValue`高16位是当前GPIO读回掩码，`measuredValue`是逻辑折算电压；最终记录的高16位仍是测试期间成功置高的通道掩码。`gBoardPwmDidoSnapshot`同时保留当前阶段、已保持时间和实时读回，最终输出及使能读回必须恢复为0。若DSP读回通过但端子仍为0V，应继续检查缓冲器供电、使能极性和缓冲器输入/输出网络。

### 无硬件回归测试

使用同一Qt Kit在独立构建目录配置`-DHPD_BUILD_TESTS=ON`，构建`HpdHostTests`后运行`ctest --test-dir <构建目录> --output-on-failure`。测试进程需要Qt及MinGW运行库位于PATH中。用例只连接本机模拟DSP，覆盖人工确认停留超过3秒、PASS/FAIL判定、无有效DO结果不弹窗、旧确认作废及真正无响应时超时；不会连接实板或产生输出。

### 驱动故障DI

低空经济统型板V01使用`0x0320 DRIVER_FAULT_DI_EXTERNAL`分组检查四路驱动故障数字输入：X3/第一套为`D_FLT_1U/GPIO10`、`D_FLT_1D/GPIO26`，X4/第二套为`D_FLT_2U/GPIO74`、`D_FLT_2D/GPIO75`。Qt选择X3或X4后，下位机只监测所选两路，另一侧电平不参与判定。所选两路都出现高、低电平及翻转时本组PASS；无变化最多等待30秒，静态高电平不能单独判通过。

Qt逐路显示`PASS/未通过/未选择`；即使组内只有一路完成，也会保留该路的PASS，但主结果保持FAIL或TIMEOUT，避免漏掉同组断线。新一轮测试清除上轮逐路显示，日志保留历史。协议继续使用高/低/翻转掩码，最小值和最大值字段均为本次监测掩码。普通三路DI及其他故障测试的全通道判定不变。本变更需要同时更新Qt及DSP固件，不由Qt把旧固件的FAIL/TIMEOUT改成PASS。

信号发生器的`COM`接板卡`DGND`，`OUT`同时接所选X3或X4组的两路板端5V输入调理端；开始后在0V/5V间切换并保持到结果返回。结束后先关闭输出再换组，禁止跨X3/X4并接，禁止将5V直接接到DSP GPIO。未来PLC的24V DO必须经过兼容电平转换。该项仅单项运行，实板验证前状态为`待验证`。

### 保护阈值与故障清除

`0x0321 PROTECTION_THRESHOLD_XINT_CLEAR`仅供低空经济统型板V01单项测试，实板验证前显示`待验证`，不加入一键外设测试。Qt提供14个选择：六路电流高端、六路电流低端和两路母线过压。电流正常值为`2.5V`，高端故障用`4.9V`（不得超过`5.0V`），低端故障用`0.1V`；母线正常值为`3.0V`，过压故障用`4.0V`。`OUT`只接所选X3/X4模拟量端子，`COM`接同组`AGND`。

测试依次验证ADC阈值、对应低有效故障输入`D_OC1/GPIO77`、`D_OC2/GPIO76`、`D_UOV1/GPIO82`或`D_UOV2/GPIO83`、高有效`D_BRK/GPIO133`上升沿外部中断，以及低有效`D_ERR_CLR/GPIO11`清除脉冲。启动后有30秒用于设置正常电压；界面进入“等待故障触发”后另有30秒用于切至故障值。ADC一旦达到阈值，保护故障位、`D_BRK`和外部中断有10秒响应时间，超时则FAIL并退出忙状态。完整保护链触发后恢复正常电压，固件输出清除脉冲并检查故障解除。不要向这些DSP数字管脚直接注入电压。

保护测试采用非阻塞状态机，等待期间TCP状态查询保持可用。实际时间由CPU Timer1的1MHz计数计算，不再依赖主循环执行次数。CCS中的`gBoardAdcProtectionSnapshot.phase`为`1/2/3/4`时分别表示等待正常基线、等待故障、等待恢复、完成，`waitSampleCount`显示当前阶段已等待的毫秒数。等待正常基线时，若ADC电压已正常但对应保护信号仍处于锁存状态，DSP每1秒自动重发一次低有效故障清除脉冲。ADC进入故障阈值后，保护故障位的响应判定窗口为10秒。`D_BRK`是所有硬件故障的总故障信号，不作为单路阈值测试的基线门槛；若它在测试前已为高，仍继续验证当前ADC阈值和对应`D_OC/D_UOV`，但不判定`D_BRK`上升沿与外部中断通过。Qt在测试期间约每200毫秒刷新`D_OC1/D_OC2/D_UOV1/D_UOV2/D_BRK/D_ERR_CLR`电平。运行记录携带当前低有效故障掩码、`D_BRK`初始/当前电平以及`D_ERR_CLR`当前电平。保护记录`rawValue[27:25]`固定为V2格式标识`101b`，Qt发现旧格式后立即停止测试并提示重新下载DSP固件。最终保护记录`rawValue[31:28]`保存选择编号，`[24:16]`保存九项阶段状态，`[15:12]`保存目标保护输入位，`[11:8]`保存触发故障掩码，`[7]`表示测试中已输出清除低脉冲，`[6]`保存`D_ERR_CLR`当前电平，`[5]`和`[4]`保存`D_BRK`初始/最终电平，`[3:0]`保存结束时正常掩码。驱动复位单路输出保持高电平10秒，期间Qt约每200毫秒显示所选复位GPIO的数字读回与已保持时间，然后DSP自动恢复全部复位输出为低电平。

`0x0322 DRIVER_RESET_DO_EXTERNAL`仅供低空经济统型板V01单项测试，实板验证前显示`待验证`，不加入一键外设测试。四路为高电平有效输出：`D_URST1/GPIO80`、`D_DRST1/GPIO81`、`D_URST2/GPIO78`、`D_DRST2/GPIO79`。选定一路后输出高电平约10秒再恢复低电平，其余三路保持低电平，Qt实时显示DSP数字读回并在结束后要求人工确认万用表结果。

驱动复位不是DI，禁止外部注入`5V`。测试前断开主功率母线和驱动功率供电；万用表使用直流电压档，黑表笔接`DGND`、红表笔接所选复位端子。PWM、PWM_EN和POW_EN不由本测试打开。

### Test ID状态

板型确认后，Qt通过命令`0x23`逐项读取Test ID状态：

- `不具备`：当前板型无对应硬件，结果表和单项测试列表均不显示。
- `待开发`：板卡具备硬件，但下位机测试尚未实现；结果表显示，单项测试列表不显示。
- `待验证`：代码已实现但尚未在当前板型和硬件版本验证；结果表显示，单项测试列表保留并标注`[待验证]`，用于板上验证。
- `可测试`：当前板型、硬件版本和固件均已验证，可参加一键测试和单项测试。

Test ID首次同步时会在尚未测试的结果行显示`可测试/待验证/待开发`；已有`PASS/FAIL`等实际结果不会被能力状态覆盖。Qt每次启动后同步一次；同一软件运行期间断线重连并再次确认相同板型时沿用缓存和现有结果，关闭并重新打开Qt后重新执行同步流程。状态同步完成前测试按钮保持锁定；旧版下位机不支持命令`0x23`时，需要先更新DSP固件。

## ADC外部注入

ADC外部注入当前只开放给低空经济统型板V01，且保持`待验证`和单项测试模式，不加入一键外设队列。Qt先通过命令`0x24`下发测试选择、0~5V目标值和容差，再启动每通道64次平均采样。

- `0x0319 ADC_EXTERNAL_SINGLE`：保留14路模拟端子的单通道排障功能。
- `0x031A ADC_EXTERNAL_STEP1_X3`：步骤1，同时注入并测试X3上的`IU1/IV1/IW1/UDC1/T_INV1/UUV1/UVW1`。
- `0x031B ADC_EXTERNAL_STEP2_X4`：步骤2，改接端子排后，同时注入并测试X4上的`IU2/IV2/IW2/UDC2/T_INV2/UUV2/UVW2`。
- `0x031C ADC_PT100_MUX_EXTERNAL`：只测试PT4。GPIO24/25固定输出`S0/S1=11`，X8的`PT4+`与`PT4-`之间接120Ω电阻，读取`AD_T_DJ`。按`Uad=65*(180/2180-Rt/(2000+Rt))`计算，120Ω目标为1.688V，容差±0.100V。
- `0x031E ADC_FAULT_MUX_EXTERNAL`：已停用。`AD_FLT1/AD_FLT2`及X3/X4上的`FLT_*`模拟故障选通不再测试，Qt不显示该项，DSP状态为`不具备`。

`0x031D`原“NTC温度选通”定义已停用。`AD_T_INV1`和`AD_T_INV2`是固定对应第一、第二套驱动器温度的ADC通道，不受三位故障片选控制，分别并入`0x031A`和`0x031B`的1V注入测试。

批量记录的`rawValue[22:16]`为七路通过掩码，`rawValue[6:0]`为七路失败掩码；位0~6依次对应`IU、IV、IW、UDC、T_INV、UUV、UVW`。CCS可通过`gBoardAdcExternalGroupSnapshots[0]`和`[1]`查看两步各通道的平均raw值和端子电压。

首次验证建议从`1.000V`开始。信号发生器使用电压模式；批量测试时，`OUT`同时接当前步骤的七个调理端子，`COM`接对应X3或X4的`AGND`，另一组保持断开。禁止把0~5V直接接到F28377D的`ADCINx`引脚。板内`D5V/A5V`监测、故障反馈和电机温度专用链路不在普通外部注入范围中。
